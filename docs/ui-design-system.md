# AI Workbench UI 设计规范

这份规范负责统一视觉语言，不负责把三个平台做成同一种布局。Mac、iPad、iPhone 保留各自的交互结构，共享颜色语义、字号层级、圆角、间距和组件状态。

## 1. 平台边界

| 内容 | 归属 |
|---|---|
| 颜色语义、间距、圆角、字号、控件尺寸、状态颜色 | `src/design-tokens.css` |
| Mac 布局和 Mac 组件外观 | `src/platforms/mac/mac.css` |
| iPad 布局和 iPad 专属交互 | `src/platforms/ipad/ipad.css`、`src/utility-controls.css` |
| iPhone 布局、键盘和安全区 | `src/platforms/iphone/iphone.css` |
| 设置页业务结构 | `src/settings-redesign.css` |

禁止用全局选择器修复单个平台的问题。修改 Mac 时，选择器必须从 `.mac-shell` 开始；iPad 和 iPhone 同理。

## 2. 视觉原则

1. **内容优先**：聊天内容最醒目，工具和状态退后一级。
2. **中性色为主**：默认按钮、选中行、输入框不使用高饱和蓝色。
3. **颜色表示含义**：绿色只表示成功，黄色只表示等待或运行，红色只表示失败、停止或删除确认。
4. **图标操作轻量**：图标按钮默认透明，只在 hover、focus 或 active 时出现中性背景。
5. **不堆卡片**：消息正文、状态说明和页面区块不重复套卡片。
6. **状态只有一个来源**：同一条消息只显示一组状态文字，不在标题、正文和输入框重复表达。

## 3. 基础令牌

### 间距

只使用 `4 / 8 / 12 / 16 / 24 / 32px`。组件内部优先 4、8、12，页面区块使用 16、24、32。

### 圆角

| 名称 | 值 | 用途 |
|---|---:|---|
| `xs` | 6px | 小图标按钮、状态标签 |
| `sm` | 8px | 列表行、普通按钮 |
| `md` | 12px | 输入框、消息气泡、文件行 |
| `lg` | 16px | 模态面板和大型移动端容器 |

Mac 主界面不使用超过 16px 的圆角，不使用胶囊形状装饰普通命令。

### 字体

| 场景 | 字号 | 建议字重 |
|---|---:|---:|
| 辅助说明 | 10px | 500 |
| 时间、元信息 | 11px | 500 |
| 控件文字 | 12px | 600 |
| 紧凑正文 | 13px | 500 |
| 聊天正文 | 15px | 400-520 |
| 组件标题 | 16px | 650 |

字号不跟随视口宽度缩放，字距保持 `0`。

### 控件

| 控件 | Mac |
|---|---:|
| 小图标按钮 | 24 × 24px |
| 标准图标按钮 | 28 × 28px |
| 发送 / 停止 | 32 × 32px |
| 图标 | 14-16px |

## 4. 组件状态

### 图标按钮

| 状态 | 视觉 |
|---|---|
| 默认 | 透明背景，中灰图标 |
| Hover | 中性浅背景，主文字色图标 |
| Pressed / Active | 比 Hover 略深的中性背景 |
| Focus | 2px 中性焦点环 |
| Disabled | 保留位置，降低透明度，不响应 hover |
| Copied | 图标或短文字反馈，允许再次点击 |
| Failed | 红色图标，不铺红色大背景 |

### 主操作

- 可以发送：白灰圆形按钮，深色箭头。
- 不可发送：中性弱化，不显示蓝色。
- 任务执行：发送按钮变为红色停止按钮。
- 不同时出现“释放输入”和“停止任务”两个含义重叠的按钮。

### 列表选中

- 使用中性背景和轻边线。
- 不使用蓝色描边。
- 状态点可以使用语义色，整行不能被状态色填满。

### 消息

- 用户消息靠右，最大宽度 560px，使用中性表面色。
- 时间、编辑、复制在同一基线上。
- AI 回复正文不放大卡片，工具按钮保持透明。
- 状态标签和计时采用相同高度、字号和圆角。

### 文件

- 文件行使用轻边框和中性表面。
- 查看、下载、删除按钮采用同一尺寸和颜色。
- 删除默认不突出；第一次点击进入确认态，第二次点击才执行。

## 5. 实现规则

1. 新组件先使用 `--aiwb-*` 令牌，禁止新增近似但不同的尺寸。
2. 平台样式可以把共享令牌映射成平台变量，例如 `--mac-control-size`。
3. `!important` 只能用于隔离遗留全局样式，不能成为新增组件的默认做法。
4. 每次改动至少检查浅色、深色、侧边栏展开、侧边栏收起和独立窗口。
5. 移动端还需要检查键盘、安全区、横向溢出和内容区滚动。
