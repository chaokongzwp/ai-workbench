AI Workbench · PRD 与架构方案总览

AI Workbench 是一个 iPhone、iPad、Mac 都能用的 AI 工作台。第一版不做自动主 AI 决策，先让用户自己选择服务器、AI 类型、工作目录和发送时机。语音先作为更自然的输入方式，把人说的话整理进输入框，真正执行前仍由人确认。

已确认：隐藏 SSH 和终端复杂度 已确认：人工主控优先 进行中：语音唤醒 后置：主 AI 分流

一页结论

产品定位

不是重新做一个 Codex 或 Claude，而是做一层更好用的 Apple 风格“工作台外壳”。它连接用户自己的服务器，复用服务器上的 AI CLI、历史会话和工作目录。

核心体验

第一次连接机器后自动扫描 AI 会话，列出工作目录。之后用户选择 AI 类型和工作目录，直接打字或说话发任务，界面只显示“我说了什么”和“AI 最终回复”。

人工主控

第一版由人自己完成关键判断：选 Codex 还是 Claude，选哪个工作目录，确认是否发送，必要时停止任务。系统负责把这些操作做得足够简单。

关键原则

人负责判断和拍板，AI 负责执行。文档是唯一通信介质。每次任务最终都要给“结果、影响、验证证据、下一步”。

需求 PRD

1. 背景问题

  • 直接用 SSH、tmux 和命令行对非开发者不友好，尤其在 iPhone 和 iPad 上更难操作。
  • Codex/Claude CLI 的启动信息、警告、选择项、终端噪声会混进回复，用户只想看最终有用内容。
  • 同一台机器可能有多个项目路径，用户希望像 Codex 一样按工作目录创建和复用会话。
  • 后续要接语音，但第一版语音只做输入辅助，不自动替人判断和执行。

2. 产品目标

目标说明状态
连接机器支持 IP 和域名，保存多个服务器配置，可复制服务器配置用于同机不同路径。部分待验
扫描会话连接后自动扫描 Codex/Claude 历史，提取工作目录列表和最近使用情况。原型中
选择工作目录用户从目录列表中选择项目，之后会话与“服务器 + AI 类型 + 工作目录”一对一映射。原型中

语音输入支持唤醒、录音、转写和填入输入框；发送前仍由用户确认。唤醒已接入
多端支持iPhone、iPad、Mac 共用核心逻辑，界面按 Apple 设计语言适配。持续优化

3. 不做什么

  • 不重新训练或替代 Codex/Claude，本产品只做交互入口、调度和结果整理。
  • 不默认展示 SSH、tmux、命令窗口和完整终端日志，除非用户主动进入调试模式。
  • 不在高风险操作上自动执行，例如删除文件、发布、付款、改生产配置等。
  • 不默认永久保存全部聊天历史，历史能力后续作为可选配置。

自然对话方案

第一版语音和文字都走“人工主控”路径。系统可以帮用户听写、填充输入、停止录音、展示待发送内容，但不会自动判断任务是否应该执行。

1. 连接机器只显示名称、地址和连接按钮。高级配置收进设置页。
2. 扫描会话自动读取远端 AI 历史和工作目录，不把底层路径噪声暴露给用户。
3. 选择上下文输入栏上方只保留两个选择：AI 类型、工作目录。
4. 人工确认用户确认输入内容、AI 类型和工作目录后，再点击发送。
5. 返回结果只显示最终回复、文件变更摘要、验证证据和必要按钮。

语音输入状态

状态判断依据系统动作
正在听用户按住说话或唤醒后开始说话。持续转写，先不发送。
停顿结束检测到一段稳定停顿。停止录音，把转写内容放入输入框。
用户编辑用户修改转写内容、切 AI 类型或切工作目录。保持待发送状态。
用户确认发送用户点击发送。锁定发送按钮，创建 worker 任务。
用户停止用户点击停止或说出停止后手动确认。中断当前录音或当前 worker 任务。
风险内容用户输入里包含删除、发布、权限、生产等操作。第一版用显式确认按钮提醒，后续再交给主 AI 判断。
交互决策：先不做自动主 AI。第一版把人放在主控位置：语音只是输入，发送必须由人确认。这样可以先把连接、会话复用、工作目录选择和结果展示打磨稳定。

未来主 AI 要求

主 AI 不进入第一版主流程。后续如果要做自动分流，它的核心不是“最会写代码”，而是“最会理解人什么时候真的要做事”。它要快、便宜、稳定输出结构化结果，并能把复杂任务交给更强 worker。

理解人话

能识别闲聊、命令、否定、追问、补充条件、上下文切换和隐含对象。

不急着执行

当用户还在说、多人还在讨论、关键信息不全时，先等待或追问。

会分配任务

知道什么时候用 Codex，什么时候用 Claude，什么时候只需要自己回答。

结构化输出

稳定返回 action、agent、workdir、question、risk、userVisibleText。

风险意识

删除、发布、权限、生产、资金相关操作必须先让用户确认。

文档意识

复杂任务完成后沉淀成 PRD、方案、状态表和验证证据。

鉴权与安全

问题建议方案说明
GPT Pro 能否直接当 API 用不建议按这个设计。ChatGPT Pro 和 API 平台通常是两套授权与计费体系。Pro 可用于远端 Codex CLI 登录；未来如果启用主 AI API，再走 API Key 或短期 Token。
短期 Token 怎么做App 请求自己的后端，后端换取短期访问凭证。客户端不保存长期密钥，便于吊销、限流、统计和切换模型供应商。
服务器密码怎么存iOS/iPadOS 用 Keychain，Mac 用 Keychain 或 safeStorage。文档、日志、Git 仓库里都不能出现密码和长期密钥。
Windows 远端机器SSH 连接可以支持，但扫描和启动命令需要 Windows 适配层。路径、Shell、进程管理和会话复用都要按 Windows 单独封装。
高风险任务第一版由界面和用户显式确认兜底。确认后才交给 worker；确认记录应进入本地任务日志。未来可由主 AI 辅助识别风险。
安全红线：不要把 OpenAI Key、服务器密码、Apple 证书、私钥写进前端代码、HTML 文档、Git 提交或可复制日志里。调试界面也默认隐藏敏感内容。

验收标准

  • 新用户只需要输入机器名称、地址和登录信息，就能完成连接，不需要理解 SSH 命令。
  • 连接成功后自动扫描 AI 历史，列出工作目录，用户选择一个目录即可开始。
  • 输入栏上方只有两个核心选择：AI 类型、工作目录。
  • 第一版不自动替用户选择模型、目录或执行任务，发送前必须由用户确认。
  • 聊天内容只显示用户发出的内容和 AI 最终回复，不展示启动 banner、TUI 选择项和无关终端输出。
  • AI 回复前发送按钮禁用；用户可以停止当前任务。
  • 风险操作必须先确认；用户拒绝后不会继续执行。
  • iPhone、iPad、Mac 都能正常布局，侧边栏可收起，顶部只显示当前会话名称。
  • 敏感信息不出现在 HTML、Git、日志和截图里。

待确认问题

问题为什么重要建议默认值
未来是否启用主 AI影响成本、稳定性和自动化边界。第一版不启用；后续再评估 OpenAI GPT-5.4 mini 或其他 provider。
语音方案影响实时性、费用和隐私。短期做语音输入和人工确认，后续再接实时语音模型。
是否保存历史影响隐私和跨设备体验。默认不保存完整聊天，只保存会话映射和必要状态。
Token Broker 部署位置影响 App Store 发布和密钥安全。独立后端服务，支持短期凭证和限流。
